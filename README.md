# FUEL · 每日营养

把每日摄入变成一座会响应的营养反应堆。基于用户提供的 Vue 营养记录页面重新设计，保留 16 种食物的每 100 g 数值，以及蛋白质 140 g、碳水 130 g、脂肪 55 g 的目标。

## 使用

- 选择食物、输入实际克数、点击「记入今日」。支持小数克数、快捷份量和删除记录。
- 点击选择框上方的「添加食物」，填写名称与每 100 克的蛋白质、碳水、脂肪克数（支持小数，没有则填 0）。「保存并选用」只添加到食物库，不计入今日摄入；随后按实际重量记录。重复名称会提示，不能覆盖原有食物。
- 自定义食物存入当前浏览器的 `food-tracker-custom-foods`，刷新及跨日保留；独立于每天的饮食记录。换设备、网址或清除浏览器网站数据后不会自动保留。保存失败时表单保留输入并提示，不虚报成功。
- 三条轨道的实心填充分别表示三种营养素的目标完成度；细小游动亮点和外围碎片是装置动效，不代表额外摄入。
- 反应堆铺满视口并固定在整页背景中，摄入读数、营养卡片和记录表单浮在前景。点击「探索核心」进入沉浸视图。可以拖动旋转、滚轮或按钮缩放、暂停、复位、展开／重组核心，或播放能量脉冲。脉冲仅播放视觉效果，不修改记录。
- 每次有效新增记录，从按钮位置和周围空间发射粒子涡流（流畅 160 / 均衡 650 / 最高 2,800），带发光拖尾、延迟核心爆亮、碎片震动和三层冲击波。删除、刷新和读取历史记录不会触发充能。暂停或系统减少动态效果偏好会关闭强动态特效。
- 能量为 4 × 蛋白质 + 4 × 碳水 + 9 × 脂肪的估算。食物数值原样沿用，未替换为网络食物库。
- 数据只存在当前浏览器的 `food-tracker` localStorage 中；不同域名或设备不会同步。同域可兼容原有记录格式；直接打开旧本地 HTML 的浏览器数据不会自动跨域迁移。
- 根据本机日期切换当天，页面恢复焦点及记录前也会检查日期。刷新从记录重新计算摄入，避免增减累积误差。损坏数据另存 `food-tracker-backup`。

## 自适应画质

首页和沉浸视图均可选择「自动 / 流畅 / 均衡 / 最高」，偏好保存在当前浏览器的 `food-tracker-graphics-quality`。

| 档位 | 注入粒子 / 拖尾 | 背景星点 / 碎片 | 画面像素上限 | 帧率上限 | 辉光 / 折射 |
| --- | --- | --- | --- | --- | --- |
| 流畅 | 160 / 0 | 72 / 6 | 65 万 | 30 | 关闭 / 关闭 |
| 均衡 | 650 / 100 | 180 / 16 | 130 万 | 60 | 降分辨率 / 关闭 |
| 最高 | 2,800 / 933 | 480 / 42 | 320 万 | 60 | 开启 / 开启 |

- 自动模式默认均衡；触控主指针、已知不超过 4 个逻辑处理器或 4 GB 内存时默认流畅。浏览器不提供硬件信息时不会假定为高性能显卡。
- 至少 8 个逻辑处理器且内存未报告或至少 8 GB 的非触控设备，在模型加载预热后，连续三段约 2.2 秒采样均达到 56 FPS、平均绘制调用小于 8 ms，才尝试最高档。充能中的采样不用于升级。硬件信息仅作初筛，实际帧间隔决定是否保留最高档。
- 自动模式持续掉帧或绘制耗时过高会逐档降低；严重掉帧更快降低。降档后本次场景不再自动升回，避免反复切换。手动档位不自动改变，重新选择自动可重新检测。
- 高分屏受渲染像素总量约束；普通档减少页面毛玻璃，关闭额外全屏闪光。暂停后仅在进度或交互变化时重绘；页面隐藏、场景离屏或背景被沉浸视图替代时取消绘制调度，恢复后重新采样。
- 策略与调度通过模拟时间测试；尚未在不同实体设备上进行 FPS 对比测量。

## 每日目标

点击首页「设置目标」：

- 手动模式可输入蛋白质、碳水、脂肪的每日克数（0.1–1,000 g）。实时显示按 4/4/9 换算的总能量；点击保存才生效。
- 自动模式使用生理性别参数、年龄、身高、体重、活动量和维持／温和减脂／缓慢增重意图。先估算，再确认采用；可以转到手动模式调整克数。修改资料后旧预览立即失效，保存时重新计算。
- 首次使用沿用原目标 140/130/55 g。目标、来源和已采用估算的个人资料存入 `food-tracker-goal-settings`，跨日保留，与食物库、当天记录分开。保存失败不修改当前目标。自动估算没有远程 API，不向 WebMCP 暴露个人资料；WebMCP 只返回当前营养目标。
- 保存后主界面、三条 3D 轨道、目标完成度、剩余量、总能量和沉浸视图均读取同一组目标。不会更改已吃的食物或数量。

计算方法：Mifflin–St Jeor 静息能量 = 10 × 体重 kg + 6.25 × 身高 cm − 5 × 年龄 + 性别常数（男性 +5，女性 −161）。乘活动系数 1.2 / 1.375 / 1.55 / 1.725；维持不调整，减脂 ×0.9，增重 ×1.1；按蛋白质 25%、碳水 45%、脂肪 30% 的能量比例换算克数，四舍五入到 0.1 g。界面总能量从最后的克数重新计算，以免显示不一致。

±10% 和 25/45/30 是产品提供的起始方案，并非研究要求所有人采用的唯一标准，也不承诺减重速度。活动系数仅为近似。自动模式限制在 18–80 岁、120–230 cm、30–300 kg，一般健康成年人；孕哺期、需特殊营养方案者使用专业目标。体重偏低（BMI <18.5）不生成减脂方案。女性结果低于 1,200 kcal、男性低于 1,500 kcal，或结果高于 6,000 kcal 时，停止自动建议，不静默截断目标。这些是本工具的保守适用边界，不是适用于每个人的医学安全阈值；低于 1,200 kcal 的手动目标会显示核对提示。

依据（2026-09-10 核对）：

- [Mifflin 等，1990，原始公式研究](https://pubmed.ncbi.nlm.nih.gov/2305711/)。研究年龄为 19–78 岁，本工具对成年边界的轻微扩展仍标记为粗略估算。
- [My nutrition index，活动系数](https://pmc.ncbi.nlm.nih.gov/articles/PMC8862522/)。
- [National Academies，宏量营养素分配范围](https://www.ncbi.nlm.nih.gov/books/NBK545442/)。25/45/30 位于成人蛋白质 10–35%、碳水 45–65%、脂肪 20–35% 的能量比例范围内。
- [NIDDK，体重规划工具适用范围](https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner)。本工具未实现 NIDDK 的动态体重模型。
- [成人肥胖生活方式干预综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC7027681/)，低能量摄入方案需要结合个人情况确定。

## 开发

Node.js 22.12+。

```sh
npm ci
npm run dev
npm test
npm run build
```

Vue 3 + Vite + Three.js。源码沿用原页面的 Vue 技术路线。本地入口 `src/App.vue`，营养计算 `src/nutrition.js`，三维场景 `src/orbit.js`。

## Blender 工程

- `art/fuel-core.blend`：可编辑源工程，保存于加入预览相机灯光之前。
- `art/build_core.py`：可重复生成的建模脚本，全部几何为本项目原创。
- `public/models/fuel-core.glb`：网页模型，约 627 KiB。
- `art/core-preview.png`：Blender 渲染检查图，不代表浏览器截图。

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python art/build_core.py
```

核心包含晶体光学外壳、发光内芯、金属支架、紧固件、双层万向环与三色卫星。轨道、漂浮碎片和注入粒子在 Three.js 中实时生成。手机使用较小渲染比例；场景离屏、页面隐藏、打开沉浸视图后暂停背景场景；尊重系统减少动态效果偏好，提供 WebGL 不可用时的二维进度视图。
